# Где мы сейчас

Снимок состояния на 18 августа 2026. Обновлять при заметных сдвигах —

## Сайт

Живёт на своём домене: **http://lindaconcerts.ru** — отдаётся GitHub Pages из
ветки `main` репозитория `pqresty/linda-site` (папка `site/`). Исходники — в
ветке `source` того же репозитория, порядок работы описан в `README.md`.

Старый адрес `pqresty.github.io/linda-site/` отдаёт 301 на домен, прежние
ссылки продолжают работать.

**HTTPS работает и включён принудительно** — 18 августа проверено с внешних
точек в пяти странах: `https://lindaconcerts.ru` отдаёт 200,
`https://www.lindaconcerts.ru` — 301 на апекс, SSL Labs ставит оценку A,
`http://` сам переводит на `https://`. Сертификат покрывает оба имени.
Переезд на домен закончен.

**Важно: с рабочего Мака этого не видно.** TLS к адресам GitHub Pages отсюда
не устанавливается — порт открыт, рукопожатие висит и обрывается по таймауту,
без сертификата и без ошибки. По `http://` тот же сайт открывается. Это
фильтрация на пути, а не поломка. Один раз это уже стоило суток: молчание
локального `curl` было прочитано как «сертификата нет», и домен зря
пересоздавали в настройках Pages. Проверять только снаружи:

    https://check-host.net/check-http?host=https%3A%2F%2Flindaconcerts.ru%2F&max_nodes=5
    затем https://check-host.net/check-result/<request_id>

По той же причине `site.py check` показывает наш собственный canonical
`https://lindaconcerts.ru/` битым. Это ложная тревога, а не проблема сайта.

DNS в порядке, трогать зону не нужно: четыре A на апексе, ни одной AAAA,
`www` CNAME на `pqresty.github.io.`

## DNS

Зона живёт **в панели хостинга** (ISPmanager, аккаунт u3601068), а не в
кабинете REG.RU: у домена NS `ns1/ns2.hosting.reg.ru`. Путь — «Хостинги» →
иконка монитора у «Хостинг Host-0» → «Управление DNS».

Настроено: четыре A на апексе (185.199.108–111.153), CNAME `www` →
`pqresty.github.io.`, записи AAAA сняты. Их обязательно было убрать — иначе
посетители с IPv6 уходили бы на старый хостинг.

Почтовые записи не тронуты: MX на `mx1/mx2.hosting.reg.ru`, поддомены `mail`,
`smtp`, `pop`, `ftp` смотрят на прежний сервер.

## Как вносить правки в афишу

Заказчик присылает текстом, что убрать и что добавить. Дальше показываем ему,
что именно поменяется, и ссылку на билеты — и ждём подтверждения. Публикуем
только после него. Молча править афишу нельзя, даже когда правка очевидная.

Ссылку на билеты берём **с сайта самой площадки**. Агрегатор годится, только
если площадка не продаёт у себя; тогда в событии ставится `aggregatorOk`.
Сайт организатора (как showman.co.il по Израилю) считается прямой продажей.

## Утренняя проверка

Настроена задача GitHub Actions «Афиша» (см. `README.md`). Осталось её
включить: завести бота у @BotFather, узнать свой числовой id у @userinfobot и
положить оба значения в Settings → Secrets and variables → Actions как
`TG_TOKEN` и `TG_CHAT`. До этого задача отрабатывает вхолостую и не падает.

Веткой по умолчанию сделан `source` — иначе расписание не запускается вовсе.
Pages по-прежнему раздаёт `main`.
