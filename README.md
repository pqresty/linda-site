# Сайт Линды — исходники

Текущее состояние работ, открытые хвосты и куда нажимать в панелях —
в `STATE.md`. Здесь только про то, как всё устроено и собирается.

Здесь лежит то, из чего собирается сайт. Готовая страница попадает в папку
`site/` — у неё отдельный репозиторий, ветка `main`, её раздаёт GitHub Pages.
Эти исходники живут в ветке `source` того же репозитория и наружу не видны.

## Как добавить или поправить дату

Руками правится только `build/tour.json`. День недели считать не нужно — он
берётся из даты сам; если вписать его вручную, рано или поздно разъедется.

```bash
python3 build/site.py build    # проверить данные и собрать index.html
python3 build/site.py check    # убедиться, что все ссылки живые
python3 build/deploy.py        # сложить в site/ только то, что нужно сайту
cd site && git add -A && git commit -m "…" && git push
```

`build` останавливается на ошибках в данных и отдельно печатает замечания:
билет ведёт на агрегатор, нет сайта площадки, не указана площадка. Замечания
не мешают сборке — это список того, что стоит доделать.

## Сверка с чужой афишей

```bash
python3 build/site.py scan
```

Тянет афишу артиста с rolld и показывает, чего у нас нет. Читает машинную
разметку, а не текст страницы: в тексте у строк нет года, и ежемесячные даты
следующего года выглядели как пропущенные в этом. Отдельно предупреждает,
когда на одну дату висят два города.

Даты, которые мы сознательно не берём, записываются в `tour.json` в ключ
`ignored` — дата, город и причина. Сверка их пропускает, но одной строкой
напоминает, что решение было. Иначе одни и те же предложения всплывают при
каждом запуске, и в шуме теряется настоящее расхождение.

## Поля события

| поле | обязательно | смысл |
|---|---|---|
| `id` | да | уникальный, вида `2026-11-01-msk-lyustra` |
| `date` | да | `ГГГГ-ММ-ДД` |
| `city` | да | город |
| `venue` | нет | площадка; без неё в строке останется один город |
| `time` | нет | `ЧЧ:ММ`; без неё покажется только день недели |
| `status` | да | `on_sale` · `not_on_sale` · `unknown` |
| `ticketUrl` | при `on_sale` | ссылка на билеты |
| `country` | нет | `KZ`, `BY`, `IL` — для зарубежных дат рядом с городом |
| `aggregatorOk` | нет | площадка продаёт только через агрегатор, искать больше не нужно |

Прошедшие даты скрываются при сборке сами. Сегодняшний концерт остаётся.

## Картинки

`build/collage_dscf_test.py` пересобирает коллаж из кадров одного фотографа:
раскладывает их так, чтобы соседи не были похожи, и отгоняет светлые кадры от
левого края, где идёт текст. Затем `build/collage_manual_edits.py` возвращает
ручные перестановки — запускать в этом порядке, иначе правки затрутся.

Адреса файлов в HTML получают отпечаток содержимого (`?v=…`). Поэтому после
подмены картинки браузер берёт новую, а не показывает старую из кэша.

## Что делается само

`.github/workflows/afisha.yml` — задача на серверах GitHub. На Маке её держать
нельзя: launchd не пускают в `~/Documents` без Full Disk Access, и такие
задачи ломаются молча.

* **9:00** — если в афише остались прошедшие даты, бот спрашивает в телеграме:
  убрать? Сам ничего не публикует.
* **днём каждые 20 минут** — слушает чат. «да» → пересборка и выкладка.
  Всё остальное, что ты напишешь боту, ложится в `build/inbox.jsonl`:
  это правки к разбору, скрипт их не толкует.
* **понедельник 10:00** — сводка: чужая афиша, битые ссылки, даты без билетов.

Расписание работает только с ветки по умолчанию — поэтому она `source`, а не
`main`. Pages при этом раздаёт `main`, это отдельная настройка.

Токен бота и номер чата лежат в секретах репозитория (`TG_TOKEN`, `TG_CHAT`).
Без них задача не падает, а тихо пропускает прогон.

Команда `/скоро` в Claude Code запускает поиск билетов по датам без ссылок.

## Что не хранится здесь

Исходные фотографии — в папке `фото сайт` рядом с проектом. Они весят на
порядок больше сайта и в репозиторий не кладутся; скрипты берут их оттуда.
